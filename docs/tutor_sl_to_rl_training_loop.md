## 1) What the supervised-learning board is saying

Nguyen wrote this objective for image classification:

```text
minimise over θ :   average of  loss( f(x; θ) , y )

# in words: make the network’s guess match the answer key
```

### Plain English, word by word

| Symbol | Meaning in his board | Everyday meaning |
|---|---|---|
| `x` | an image | the input |
| `y` | the correct label (e.g. "cat") | the answer key |
| `f(x; θ)` | the network's guess | "what do you think this is?" |
| `θ` | the network weights | the knobs we can turn |
| `loss(·,·)` | the loss | "how wrong were you?" |
| average over N | average over the dataset | don't just look at one example |
| minimise over θ | choose θ to make loss small | learn |

He then wrote the **implementation template**:

```text
net = ResNet18()          # the model f(·; θ)
opt = ...                 # the optimiser (SGD / Adam)

preds = net(x)            # 1 PREDICT
loss  = (preds - y)**2 / N   # 2 SCORE
opt.zero_grad()
loss.backward()           # 3 DIFFERENTIATE
opt.step()                # 4 UPDATE   (θ ← θ − α · gradient)
```

### The four beats of every supervised training step

1. **Predict** — `preds = net(x)`
2. **Score** — `loss = ...`
3. **Differentiate** — `loss.backward()`
4. **Update** — `opt.step()`

That is the whole story of supervised learning. There is a fixed dataset
`(x, y)`. The answer key `y` already exists. We only learn to match it.

## 2) Why RL looks different (but the four beats stay)

In trading / RL:

- There is **no label** `y` saying "the correct action was Buy".
- The agent must **act**, then the market replies with a **reward**.
- The "dataset" is **generated by the policy itself** (rollouts / trajectories).

So Nguyen's template becomes:

| Supervised (his board) | Reinforcement learning (ours) |
|---|---|
| fixed dataset `(x, y)` | trajectories collected by acting in the market |
| loss `ℓ(f(x), y)` | PPO score `L_CLIP` + value loss `L_V` |
| minimise loss | maximise expected reward (via PPO surrogate) |
| one network | policy `π_θ` **and** critic `V_φ` |

The four beats remain: **predict → score → differentiate → update**.
Only the meaning of "score" changes.

## 3) General RL training template (Nguyen style)

Objective (Iteration 1, one day = one trajectory):

```text
maximise over θ :   average over K episodes of
                    [ sum of  γ^t · r_t  over the day ]

actions:   a_t  ~  π_θ(a | s)
```

In practice we use PPO, which replaces the raw return with a **stable
surrogate** that uses advantages `A_t` from the critic.

### Pseudocode template (mirror of his ResNet board)

```text
# MODEL
policy = PolicyNet()          # π_θ  — chooses Hold / Buy / Sell
critic = ValueNet()           # V_φ  — estimates "how good is this state?"
opt_pi = Adam(policy)
opt_V  = Adam(critic)

# DATA  (not a fixed CSV of labels — we create it by acting)
B = ROLLOUT-EPISODE(prices, policy, fee, cash0)
# B contains (s, a, r, s_next, mask)

# SCORE
A    = advantages(B, critic)           # how much better than expected
L_pi = - PPO_CLIP(policy, B, A)        # maximise clipped surrogate
L_V  = MSE(critic(s), returns)         # critic should match returns

# DIFFERENTIATE + UPDATE  (same four beats as ResNet board)
opt_pi.zero_grad();  L_pi.backward();  opt_pi.step()
opt_V.zero_grad();   L_V.backward();   opt_V.step()
```

### Side-by-side with his board

```text
HIS BOARD (classification)          OUR LOOP (trading)
─────────────────────────          ─────────────────────────
net = ResNet18()                   policy = PolicyNet(); critic = ValueNet()
preds = net(x)                     probs = policy(s);  a ~ probs
loss  = (preds-y)**2 / N           L_pi = PPO_CLIP(...);  L_V = MSE(...)
loss.backward()                    L_pi.backward(); L_V.backward()
opt.step()                         opt_pi.step(); opt_V.step()
```

That is what he means by "write it like this".

## 4) Our concrete mapping (Iteration 1)

| Piece | Our choice |
|---|---|
| State `s` | `[ΔP, C, n]`  — price change, cash, share count |
| Actions | `{0: Hold, 1: Buy one, 2: Sell one}` |

| Reward | `r = W_next − W` |

## 5) Experiments section — what Nguyen's outline demands

### 5.0 First: prove you can train a policy on a toy game

From New Recording 47 (23 July): before trading, implement **policy-based** RL
on Flappy Bird (or similar). When the bird learns, your training loop is
correct. Trading has no known “right answer”, so it cannot debug your code.

### 5.1 Baselines (each must have a clear objective)

For Iteration 1, keep baselines stupidly simple so an ML examiner
understands them with no finance background:

| Baseline | Rule | Objective / what it maximises |
|---|---|---|
| **Do-nothing** | always Hold | zero trading; wealth only moves with existing shares (starts at 0 shares → flat cash) |
| **Buy-and-hold** | Buy one share at open (if affordable), then Hold | capture the day's price move with one share |
| **Random policy** | sample Hold/Buy/Sell uniformly (with mask) | sanity check: learned policy must beat chance |
| **Our PPO agent** | Algorithm 3.1 | maximise expected sum of `r = ΔW` |

Later (only after Iteration 1 works): moving-average rule, stop-loss rule,
then the old uncertainty-aware agent as an advanced comparator — not as
the starting point.

### 5.2 Metrics (report the same numbers for every method)

On each held-out day / week window:

1. **Terminal wealth** `W_T` (or `ΔW = W_T − W_0`)
2. **Sum of rewards** `sum r_t` (should equal `ΔW` if no accounting bug)
3. **Number of trades** (Buy+Sell counts) — detects hyperactivity
4. **Max drawdown of W within the day** — optional early risk view
5. Across days: **mean ± std**, and win-rate vs buy-and-hold on `ΔW`

### 5.3 Implementation checklist (smallest honest experiment)

1. One ticker (e.g. SPY or AAPL), one month of minute bars → many day-trajectories.
2. Train/test split by **calendar** (first 15 trading days train, last 5–7 test) — never shuffle minutes across days.
3. Train Algorithm 3.1 for a small budget (e.g. 20–50 epochs) with 3 seeds.
4. Evaluate all baselines + PPO on the **same** test days.
5. One equity curve plot: wealth vs minute for a representative test day.
6. One bar chart: mean `ΔW` by method.

### 5.4 Results narrative template (write this before you trust any number)

> On the held-out days, buy-and-hold achieved mean ΔW = ___.
> Random achieved ___.
> PPO achieved ___, which is ___ vs buy-and-hold.
> The agent traded on average ___ times per day.
> Failure mode: on day ____ the agent ____ because ____.

If you cannot fill those blanks from a real run, the experiment is not done.
