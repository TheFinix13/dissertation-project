## The seven rules baked into every section

1. **Define-before-use.** Every technical term gets a one-clause definition in the same sentence it first appears.
2. **One idea per sentence.** No sentence has more than two commas. Lists with three or more items become bullet lists.
3. **Work-package structure.** Implementation, evaluation, and future work all read as WP1 → WP2 → WP3 → WP4 with tickable tasks.
4. **Conservative claims.** "Extends X by adding Y", not "introduces a novel framework that…".
5. **Bounded scope.** Every chapter opens with what it does, and one sentence saying what it does not claim.
6. **No bracketed labels in headings.** No `[The Goal]`, no `[The Innovation]`.
7. **Every number has a citation or a code reference.** Either a `\cite{}` or a pointer to a file/notebook/script in this repository.

The writing checklist at the bottom of this document is built from these seven rules and should be run against every paragraph before it's locked in.

## Glossary (new — fold-out, one page)

Lifted directly from the walkthrough notebook glossary. Each term gets one sentence.

| Term | One-sentence definition |
|---|---|
| PPO (Proximal Policy Optimization) | A learning algorithm for AI agents that take sequential actions; updates the agent's policy carefully so each update doesn't overshoot. |
| LSTM (Long Short-Term Memory) | A type of neural network designed to learn patterns in sequences, such as daily stock prices. |
| MDP (Markov Decision Process) | The standard mathematical frame for sequential decision problems under uncertainty. |
| DeepAR | A probabilistic forecasting architecture (Salinas et al., 2020) that outputs both a predicted mean and a predicted spread. |
| Sharpe ratio | A measure of risk-adjusted return — return divided by the standard deviation of returns. Higher is better. |
| Maximum drawdown | The worst peak-to-trough percentage drop in portfolio value over a period. Lower is better. |
| Capital preservation ratio | The ratio of current portfolio value to the running high-watermark. We target above 95%. |
| Aleatoric uncertainty | Uncertainty about *the data* — how chaotic the market is. |
| Epistemic uncertainty | Uncertainty about *the model itself* — how unfamiliar today's data looks to the forecaster. |
| Seed | A random starting point for training; multiple seeds prove results aren't lucky. |
| Walk-forward | An evaluation method where training and test windows slide forward through time. |

## 3.0 (NEW) Overview in plain English (target: 0.5 pages)

**Three paragraphs as a non-technical on-ramp before the formal notation.**

1. The trading task is set out as a sequential decision problem. Every day the agent observes the market and its own portfolio, chooses how much to buy or sell, and is rewarded for growing the portfolio.

2. Mathematically this is a Markov decision process — the standard mathematical frame for sequential decision problems under uncertainty. Section 3.1 sets out the full notation.

3. The agent is paired with a forecaster that emits both a prediction and a confidence interval around that prediction. The width of that confidence interval is the uncertainty score (Section 3.4) and is what the dissertation feeds back into the agent (Section 3.5).
